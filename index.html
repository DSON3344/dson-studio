Any business or product information shared for the project is used only within that project's scope and is not disclosed elsewhere. A formal NDA can be signed before kickoff if your project needs one.

The client buys and owns the domain — ownership and renewal responsibility stay with the client regardless of the studio relationship. WEB APPLICATION · 2026

VisionLogic AI

Intelligent Design Evaluation Platform

ProblemDesign feedback in education is slow, subjective and inconsistent; 53% of 68 surveyed students said inconsistent grading had affected their GPA.

ApproachA web platform that scores uploaded work across six category-specific metrics using a constrained AI evaluator, returning a radar chart and a written report in three languages.

OutcomeDelivered solo in 13 weeks: research, UI design, full-stack build and deployment. Rebuilt from the ground up at week 9 after the original architecture proved unmaintainable.

RoleSolo Designer & Full-Stack Developer
Timeline13 Weeks (Jan–Apr 2026)
Live Sitevisionlogic-ai.dson.site ↗
Node.jsExpressMongoDB Gemini AI APIHTML/CSS/JSVercel

The Problem

Design feedback in academic settings has always been broken. A student submits their best work, waits days for a review, and gets back something vague — “the composition feels off.” Two lecturers, two different verdicts. No rubric, no consistency, no benchmark.

This directly impacts GPA: a survey of 68 participants found 53% reported that inconsistent grading had negatively affected their academic performance, and 26.5% strongly agreed a standardized, objective evaluation tool was needed.

The Concept

VisionLogic AI is a web-based intelligent design auditor — designers upload their work and receive instant, structured, AI-powered feedback scored across six professional metrics. The goal: replace subjective human critique with a consistent, data-driven framework, without sacrificing an experience that's intuitive for students at any skill level.

Upload. Analyze. Improve.

Design Process

Research & problem definition — a literature review confirmed no local tool existed for standardized design evaluation in Malaysia; a PESTLE analysis aligned the platform with Malaysia's National AI Roadmap and MyDIGITAL Phase 3 (2026–2030). Every decision was filtered through the Technology Acceptance Model (perceived usefulness + ease of use).

Wireframe to high-fidelity — from low-fidelity sketches and user-flow diagrams to a complete high-fidelity prototype in Figma, anchored in a dark-first aesthetic with cyan (#40CFC4) accents and a dual-mode sidebar (Guest / User).

  • Landing page — hero with animated CTA and interactive guide
  • Analyze dashboard — upload zone, category/tone selector, live Radar Chart
  • History page — filterable evaluation log with export
  • Account & settings — profile, language (EN/CN/MY), legal terms

Directions that were dropped — the first build shipped both a light and a dark theme. Testing with real uploads killed the light one: user-submitted designs often contain large pale areas, and against a light interface those regions lost the contrast needed to read the annotations drawn over them. The interface had to stay darker than anything a user would upload, so dark-only became a functional constraint rather than a style preference.

The background was originally a flat gradient. Feedback from the project supervisor was that it read as empty for a platform whose subject is technical analysis, so it was rebuilt with structural, technical motifs that reinforce what the tool actually does.

The AI Evaluation Engine

Powered by Gemini AI (Flash model) via Google AI Studio, governed by a custom prompt-engineering framework: a Professional Design Director persona, 90/10 visual-to-context weighting, structured JSON output rendered as a Radar Chart plus a 2-page report — in English, Chinese, or Malay.

Each design is scored across six metrics tailored to its category — UI/UX (Usability, Hierarchy, Consistency, Accessibility, Spacing, Flow), Graphic Design (Layout, Typography, Color Harmony, Visual Hierarchy, Impact, Whitespace), or Photography (Exposure, Color Mood, Texture, Balance, Contrast, Detail).

The Rewrite

The first working prototype ran on Ollama — a locally hosted model. It scored designs, and it proved the concept. It also consumed enough resources to become unstable: under load the model would fail outright, taking the entire evaluation flow down with it. A tool whose only function is producing an evaluation cannot sometimes not produce one.

Moving to a hosted model solved the reliability problem and created an architectural one. A hosted API needs a key, a key cannot live in client-side code, and the front end had been built on the assumption that it could. Fixing that meant introducing a server — which meant the existing architecture no longer fit.

The decision point came at week 9. Three weeks had been spent away from the codebase working on the interface, and coming back to it, the original implementation was no longer legible enough to extend confidently. Patching an architecture that had to change anyway, in code that would take days to re-read, was going to cost more than starting again.

The front end was rebuilt in vanilla HTML, CSS and JavaScript on a Node.js and Express backend, with the API key held server-side. Four weeks of a thirteen-week timeline remained.

The most expensive decision in the project, and the correct one.

Technical Architecture

Built on Node.js + Express — chosen over React mid-development for reliable server-side Gemini API key management. MongoDB handles auth, sessions, and evaluation history under PDPA 2010 compliance; Vercel was selected over GitHub Pages for Node.js runtime support.

  • Multer — design image upload handling
  • Bcrypt + Express-Session — password hashing & session management
  • Nodemailer — OTP authentication emails
  • Puppeteer — automated PDF report generation

Challenges & Solutions

Model reliability — the local Ollama model was unstable under load; migrating to a hosted Gemini model traded resource cost for consistency. See The Rewrite above.

Gemini prompt calibration — early evaluations were inconsistent until a structured prompt system with fixed personas and enforced JSON output made the AI behave like a design director, not a generalist chatbot.

Hosting limitations — GitHub Pages doesn't support Node.js execution, so Vercel was chosen for its runtime and secure environment variables.

13-week deadline — delivered April 26, 2026, covering research, design, full-stack development, testing, deployment, and thesis submission in parallel.

What's Next

The evaluation currently identifies where a design needs work — it marks the region and scores it. It does not yet say what to do about it.

The next iteration adds a guided revision layer: instead of a marked area and a score, the user gets an ordered set of concrete steps for addressing each issue. Diagnosis is the harder half to build, but instruction is the half that changes a user's outcome — a score tells a student they are wrong, a sequence tells them how to be right.

AI PRODUCT · LIVE · 2026

Auteur

AI Screenwriter/Director Prompt Engine

ProblemThird-party video generation tools handle character motion, expression and scene well, but their story reasoning isn't good enough — users still have to plan every scene themselves, which caps output at the speed of manual scriptwriting.

ApproachA five-stage pipeline (refine → write → direct → consistency cards → generate) that reads the whole story first, then produces structured shot prompts, instead of writing scene-by-scene on the fly.

StatusCore pipeline is working end-to-end and stress-tested against a full-length story. Now live at auteur.dson.site in soft launch, while the product keeps being refined.

RoleIn-house Product · Solo Development
TimelineOngoing (started 2026)
StatusLive · Soft launch
Live Siteauteur.dson.site ↗
Node.jsExpressGemini AI API HTML/CSS/JS

The Problem

This direction came out of a real internship building AI-generated short dramas: third-party video generation tools handle character motion, expression and scene changes well, but their reasoning about story itself isn't good enough. Every scene still has to be planned by a human before the AI can execute it. That step doesn't disappear — it caps output at the speed of manual scriptwriting.

The Concept

Auteur is meant to let an AI actually understand a full story, then think like both a screenwriter and a director when producing shot prompts — so the user doesn't have to work out how to shoot every scene themselves, just feed the output straight into a third-party video tool. The bar isn't 100% fidelity, just a consistently usable accuracy.

The Five-Stage Pipeline

  • Refine — the AI reads the outline, flags issues and offers a few fix options to choose from
  • Write — structures character arcs, scene/emotional turning points and causal chains, offering a few storyline options
  • Direct — breaks episodes into scenes and shots at short-drama pacing (density is adjustable)
  • Consistency cards — generates standalone appearance-reference prompts for characters, sets and props to lock visual consistency
  • Generate — outputs the full structured shot script for every scene, including dialogue, duration and shot language

The State Engine

Early testing surfaced a deeper problem: characters would technically "appear" in the story but be absent from their own key turning points; relationships would jump from strangers to confidants with no transition; locations that had been destroyed would reappear intact with no explanation. Nothing in the pipeline was tracking how the story's state changes across episodes.

Three tracking layers were added — character state (fears and flaws), relationship state (must progress through stages, no skipping ahead), and world state (locations and factions must keep their changed status consistent across later episodes). Three separate AI cross-evaluations independently flagged this as the highest-value direction for the next stage.

Problems & Fixes

Episode count shortfalls — asking for 50 episodes produced only 25, because an exact episode count is an unreliable natural-language instruction for a single large-batch generation call; added automatic gap detection with a continuation pass to fill the shortfall.

Dropped characters in long stories — a nine-character story would get silently compressed during the writing stage, dropping most supporting characters; added a character-list extraction pass with full-coverage checks enforced through every later stage.

Rate limits and quota — Gemini's free-tier per-minute limit and peak-time 503s repeatedly broke the pipeline mid-run; added automatic retries, a configurable generation delay and resumable checkpoints so a rate-limit hit doesn't lose completed progress.

Pacing and duration — early episodes ran only a few seconds, far under the target; density presets now bind scene/shot counts to a total duration target instead of managing them independently.

What's Next

The landing page and production console are both built, and the core pipeline has been validated once against a full-length story. Auteur is now live in soft launch at auteur.dson.site.

The current focus is validating the State Engine against real output and continuing to refine how usable the shot scripts are, ahead of a wider public push.
